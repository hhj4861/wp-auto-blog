# 카테고리별 시장 키워드 → 예약 발행

기존 11시 스케줄은 유지한다: 월·수·금 생활정보, 화·목 취업, 토 건강.
매일 09:30에는 각 카테고리를 독립적으로 탐색해 보고서만 생성한다. 11시 발행 작업은
해당 카테고리의 36시간 이내 보고서를 읽고 WordPress 중복 여부를 다시 확인한다.
보고서가 없거나 후보가 소진되었으면 그 자리에서 새로 탐색한다.

## 선정 근거

1. 취업·생활정보·건강별로 검색 범위를 정하는 시드를 분리한다. 시드는 발행 주제가 아니다.
2. 네이버 검색광고 API가 실시간 반환하는 연관 키워드·월 PC+모바일 검색량에서 신규 후보를 수집한다. AI가 시장 검색량이나 검색 결과를 만들어내지 않는다.
3. 최소 500회 이상의 실측 후보에서 발행 이력을 먼저 제외한다. 검색량 상위 후보와 구체적인 질문·조건·서류·준비물 등의 중소 검색량 후보를 섞어 최대 120개를 탐색 대상으로 만든다. 검색량 상위 60개만으로 후보를 제한하지 않는다.
4. 공개 글·초안·예약 글 제목과 API에 노출된 SEO 초점 키워드, 기존 레지스트리, 완료된 큐, 누적 키워드 이력을 대조한다. 조회 실패를 미발행으로 해석하지 않는다. 한 번의 전체 카테고리 탐색에서도 먼저 선정된 키워드는 이후 카테고리에서 제외한다.
5. Codex는 먼저 실측 목록에서 조사할 검색어만 고른다. 최대 2회, 회당 6개를 조사하며, 출처 실패 등으로 선정 수가 부족하면 조사하지 않은 다른 후보를 고른다. AI가 제목이나 출처 URL을 먼저 지어내게 하지 않는다.
6. Google Custom Search의 실제 결과 URL·제목·요약을 우선 읽으며, 불가하면 DuckDuckGo를 조회한다. 실제 엔진을 기록하고 같은 도메인의 여러 검색 결과도 각각 경쟁 비중에 반영한다. 월 5만 회 이상이면서 정부·대형 사이트 비중이 40%를 넘는 키워드는 제외한다. 두 검색 경로가 모두 실패하면 월 5만 미만의 구체적인 질문형 키워드만 Codex 구독의 내장 웹검색으로 조사한다.
7. 검색 결과의 공식 URL과 공식 도메인 제한 검색으로 찾은 URL의 본문을 읽는다. 공식 자료가 없으면 Codex 내장 웹검색으로 보충한다. Codex 경로는 JSONL의 완료된 `web_search/search` 활동과 `open_page`의 실제 URL을 확인한 뒤 별도 HTTP 요청으로 공식 본문을 다시 읽는다. 최종 답변에 적힌 URL만으로는 근거를 인정하지 않는다. 그 후 검색 의도·카테고리·독자 가치·근거·마감을 검토해 제목을 확정한다. 순위 자료가 없는 경우 공식 본문에서 확인할 수 있는 질문과 독자 가치만 검토하며 경쟁 우위를 주장하지 않는다.
8. 수요(log 스케일, 최대 35점), 대형 사이트가 적은 검색 결과의 비중(최대 40점), 질문의 구체성(최대 15점), 관심도 변화(-5~10점)로 우선순위를 매긴다. 검색량의 점수 상한을 둔다. Codex가 열어 본 페이지는 검색 순위 표본이 아니므로 `evidence_mode=official_pages`, `organic_provider=null`, 검색 결과·도메인 목록은 빈 배열, 점유율은 null로 기록하고 경쟁 기회 점수는 0점이다. 실측 경쟁도와 혼동하지 않으며 점수 항목을 함께 저장한다.

네이버 월간 검색량은 Google 검색량이 아니다. 광고 경쟁도는 기록만 하며 SEO 난이도로
사용하지 않는다. 검색 결과 도메인 비중 역시 SEO 난이도나 순위를 정확하게 예측하지 못하는
보조 지표다. Google Trends의 완결된 최근 7일 대비 이전 7일 상대 관심도 변화를 조회해 -5~10점으로 보정한다.
표본 부족·조회 실패는 trend_growth=null로 기록하고 가산하지 않는다. 이는 절대 검색량 증가율이 아니다.
현재 시의성은 측정 가능한 관심도 변화와 공식 자료의 마감 검토로 판단한다. Google Grounding은 실측 검증에서 근거 누락이 반복되어 필수 후보 수집 경로에서 제외했다.

## 작성 연결과 보류

선정 결과는 data/category_market_topics.json에 카테고리·검색어·검색량·출처·검색 결과
도메인·점수·탈락 이유·선정 시간을 기록한다. 발행 시에만 선택 카테고리의 후보를 기존 큐에
추가한다. BLOG_REQUIRE_MARKET_TOPIC=1이면 해당 카테고리의 신선한 검증 후보 중 최고 점수를
소비한다. 기존 수동 큐 항목은 보존하지만 예약 시장선정 경로에서는 소비하지 않는다.
선정 실패·자료 미확인·검증 후보 소진 시 기존 큐/임의 외항사 주제로 대체하지 않는다.

선정 결과의 `intent`(독자의 질문), `gap`(본문에서 제공할 구체적인 가치), `source_url`을
큐 → 파이프라인 → 본문 작성기에 전달한다. 작성기는 선택한 공식 URL을 다시 읽고,
해당 질문과 표·체크리스트·절차를 작성 프롬프트에 반영한다. 이 경로는 선정 후 Gemini로
출처를 다시 찾지 않는다. 출처가 사라졌으면 발행을 보류한다. 생성된 제목과 SEO 초점 키워드가
선정한 키워드를 유지하는지도 검사한다.

본문 작성과 검수는 기존 Codex 구독 경로와 편집·출처·대표 이미지 게이트를 사용한다.
검색량이 높아도 실제 Google 유입·수익을 보장하지 않는다. 이 변경은 새로운 시장 주제 선정이며,
기존 글의 GSC 노출 순위를 후보 생성의 출발점으로 사용하지 않는다.

새 보고서는 `selection_version=3`다. 이전 버전이나 검색 의도·읽은 공식 본문이 없는 캐시는
재사용하지 않는다. `serp`는 실제 검색 결과를 요구하며, `official_pages`는 실제 검색·열람 기록과
질문에 사용한 모든 공식 출처의 본문·확인일·열람 URL 연결을 요구한다. 조사 요청 하나가 실패해도
이미 검증한 다른 후보는 보존한다. 우선순위 점수는 예상 방문자 수나 Google 순위가 아니다.
독자의 질문에 답하고 검색 결과 대비 추가 가치를 제공한다는 편집 기준은
[Google의 유용한 콘텐츠 지침](https://developers.google.com/search/docs/fundamentals/creating-helpful-content)을
참고하며, 위 숫자와 가중치는 이 프로젝트의 탐색 기준이다.

## 확인만 실행

GitHub Actions → Blog Keyword Select → category=all 또는 특정 카테고리.
이 작업은 글을 발행하지 않는다. 구독 인증을 쓰는 실제 선정 실행은 main에서 수행한다.
main 실행은 생성된 보고서를 커밋한다. 일부 카테고리가 실패해도 다른 카테고리의 검증된 결과는 보존한다. 자동 발행은 기존 Auto Blog Post의 post-queue 작업이다.

SELECT_TOP_N의 빈 문자열은 2로 처리하며 1~5만 허용한다. 이전 건강/뷰티 전용 스캘폴드 생성은
이 선정 작업에서 제거했다. BytePulse 발행 파이프라인은 변경하지 않았다.

## 한 번 발행한 키워드 재발행 금지

시장 후보 선정, 캐시 재사용, 작성 시작 전, WordPress 저장 직전에 모두 제목/초안/예약 글과 기존 발행
레지스트리를 대조한다. 공백·대소문자·문장부호·연도(2026→2027)만 다른 키워드도 같은
키워드로 정규화한다. HTML 공백 엔티티와 전각 문자 차이도 정규화한다.
새 시장 키워드의 WordPress 발행 응답 직후 posted_market_keywords.json에 키워드와 글 ID를
누적하고 그 다음 부가 핑/레지스트리를 처리한다. 부가 작업 실패로 이미 발행한 키워드의 이력을
누락시키지 않는다. 이 이력은 글을 삭제해도 삭제하지 않는다. 재작성은 신규 포스팅이
아닌 기존 글 갱신 작업으로 별도 수행해야 한다. 동시 발행/선정은 같은 concurrency 그룹으로
직렬화한다. 초안은 중복 방지 대상으로 예약하되 공개 발행 완료로 기록하지 않는다.

## 회귀 검증

`venv/bin/python -m pytest tests/test_market_topics.py tests/test_market_search.py -o addopts='' -q`

실측 후보 → 출처 조사 → 선정 보고서 → 큐 → 발행 → 삭제 후 재선정 차단 흐름을 검증한다.
외부 검색·모델·품질 검수·WordPress는 테스트 대역이므로 이 결과는 실제 서비스 실행 증거와 구분한다.
실서비스 확인은 위 Blog Keyword Select 작업으로 카테고리별 선정 결과와 탈락 이유를 확인한다.

## 분석 모델

시장 후보 분류와 공식 자료 적합성 검토도 CODEX_AUTH_JSON 구독 인증을 사용한다.
실측 검증에서 Gemini 무료 일일 요청 한도에 도달했으므로 이 선정 경로의 Gemini 의존은 제거했다.
선정 job과 발행 job은 같은 concurrency 그룹에서 인증을 복원·갱신 저장·삭제한다.
공개 저장소의 구독 인증은 기존 guard에 따라 main의 수동/예약 실행에서만 허용한다.
검증 브랜치에서는 단위 시험을 수행하고, 실제 인증 검증은 검토·머지 후 main에서 수행한다.

Codex 웹검색은 별도 검색 API 키를 요구하지 않는다. CLI `--search`, `exec --json`을 사용하고
연구 요청에서 셸 도구를 비활성화한다. 읽기 전용 샌드박스와 자격 증명 환경 격리를 유지한다.
검색 이벤트 원문은 로그에 출력하지 않으며, 검증에 필요한 공개 URL과 고정된 상태만 남긴다.
관련 계약: [Codex 웹검색](https://learn.chatgpt.com/docs/web-search),
[비대화형 JSONL 출력](https://learn.chatgpt.com/docs/non-interactive-mode).
