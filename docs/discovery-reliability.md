# 검색·심사·발행 안정성 개선 — 2026-10-01

상태: 별도 구현 브랜치에서 관련 검증을 통과했다. 운영 main 반영과 실제 신규 발행 성공은 아직 확인하지 않았다.

## 확인한 원인과 확인할 수 없는 부분

- 최근 운영 실행 `36829739986`은 리뷰 후보 341개를 측정하고 12개를 조사 풀에 남겼지만 실제로는 2개만 조사했다. 공기청정기필터는 독립 주제 심사에서 `review_failed`로 보류됐고 삼성노트북배터리는 검색 관련성·사이트 다양성 부족으로 탈락했다. 두 원인은 다르다. 작성·발행 단계에 도달하지 않았다.
- 당시 `review_plan()`은 모델 호출과 JSON 파싱 과정의 예외를 전부 `review_failed`로 바꾸었다. 따라서 그 실행의 정확한 하위 원인이 시간 초과, 인증, 사용 한도, JSON 문제 중 무엇이었는지는 **과거 기록으로 복원할 수 없다**. 코드와 테스트로 특정 하위 원인을 실제 발생했다고 주장하지 않는다.
- `ask()`는 JSON 파싱만 한 번 재시도했다. 모델 전송 오류는 복구하지 않았다. 중복 심사와 최종 본문 심사도 서로 다른 위치에서 오류 상세를 없앴다. 하나의 검색 단계 수정으로 뒤 단계의 실패가 해결되지 않았던 이유다.
- 빈 shortlist를 받으면 조사하지 않은 후보까지 `not_proposed`에 넣었다. 첫 회차 2개를 조사하고도 남아 있던 전체 실행 조사 예산 1개를 쓰지 못한 채 풀이 소진될 수 있었다. 새 회귀는 세 번째 후보가 실제 조사와 동일한 발행 근거 검증을 거쳐 큐에 들어오는 것을 확인한다.
- 9월 9일 시장 수요 기반 선정, 9월 11일 검색 관련성·범위·현재성 심사, 9월 말 구매 질문 제한 및 출처 복구가 차례로 추가됐다. 현재 리뷰 발견 범위는 일반 인기 제품 전체가 아닌 지원하는 제품군과 구매 판단 항목이다. 기존 발행량만으로 이 조건을 충족하던 마지막 정상 버전이 있다고 단정할 수 없다.

입력 증거는 `tests/fixtures/review_independent_failure_20261001.json`에 보존했다. 공개 검색 결과·공식 발췌·실제 실패 판정이며, 성공한 모델 의견을 새로 만들어 붙이지 않았다.

## 변경

### 동일 원칙으로 기술 오류를 처리

`src/analysis_runtime.py`에서 검색, 기획, 독립 심사, 작성, 중복 심사, 최종 본문 심사가 공통 오류 분류·복구를 사용한다.

- 네트워크/서비스, 시간 초과, 빈 응답, JSON/스키마 오류만 제한적으로 재시도한다. 인증·사용 한도·모델 설정 오류와 알 수 없는 예외를 무조건 반복하지 않는다.
- 한 작업의 중첩된 전송·형식 검사도 추가 호출 한 번을 공유한다. 선정 전체의 추가 호출은 최대 4회이고 기존 25분 조사 예산도 확인한다. 이 상한은 전체 워크플로의 모든 API 요청을 합친 수가 아니다.
- 실제 내용 부적합, 좁은 답변 범위, 본문에 없는 승인 인용은 자동 승인하지 않는다. 원문·실측 검색어·검색량·최종 품질 게이트를 낮추지 않는다.
- `analysis_diagnostics`에 단계, 시도 번호, 고정 오류 코드, 경과 시간을 남긴다. 원본 예외·토큰·프롬프트·모델 응답을 진단 로그에 넣지 않는다. 선정 밖 작성·최종 심사의 오류도 고정 코드로 로그에 남긴다.
- 주제의 기술적 심사 실패를 해당 키워드의 내용 부적합 이력으로 새로 누적하지 않는다. 과거 실패 이력의 유효 기간을 일괄 삭제하지 않는다.
- 선정 중단 시 새 시각·빈 selected·오류 사유를 기록하여 기존 선정 결과가 새 실행 결과로 남지 않게 한다. 유효하지 않은 후보를 큐에 넣지 않는다.

### 조사하지 않은 후보와 탈락 후보 구분

빈 shortlist의 `purchase_intent_unclear`, `insufficient_specificity`, 미보고 후보는 남은 조사 예산에서 계속 검토한다. 명백한 범위·카테고리·정비 목적 탈락은 유지한다. 예산 때문에 조사하지 못한 후보는 `unresearched_budget_keywords`로 구분하고, 출처 검증을 통과한 것처럼 표시하지 않는다. 예산이 끝나면 남은 후보만 반복 제안받지 않고 다른 측정 풀로 진행한다.

### 유튜브 최근 인기 자료를 발견 입력으로 추가

- 각 카테고리에 맞는 고정 검색 질의 2개로 최근 90일 영상을 조회한다. YouTube Data API `search.list`의 `order=viewCount`, 한국 지역·한국어 선호를 사용하고 `videos.list`에서 게시일과 실제 조회수를 확인한다. 최대 요청 3회, 페이지 추가 조회 없음, 같은 채널은 최대 2개다.
- 이 값은 해당 검색 표본의 조회수 순이다. 유튜브 전체 인기 순위나 시계열 상승률, Google 검색량으로 표현하지 않는다. 언어 선호 설정도 모든 결과의 한국어를 보장하지 않는다.
- 모델이 제시한 시드는 최대 4개이며 제공된 영상 ID와 제목에 실제 포함된 문구만 허용한다. 모델이 만든 인기 수치·새로운 영상·임의의 검색어는 받아들이지 않는다.
- 시드로 발견한 연관어는 네이버 API에서 **각 연관어 자체의 검색량**을 다시 측정한다. 이후 중복·카테고리·검색 의도·공식 본문·독립 심사를 모두 거친다. 영상 조회수를 연관 키워드의 상승률이나 점수로 옮기지 않는다.
- API 키 없음·API 오류·유효한 최근 자료 없음은 상태를 기록하고 기존 네이버/CAK 경로를 유지한다. 새 유료 OpenAI API 경로는 추가하지 않는다. 기존 `YOUTUBE_API_KEY` Secret을 자동포스팅과 사전 키워드 선정 두 워크플로에 연결했다.

API 계약: [YouTube search.list](https://developers.google.com/youtube/v3/docs/search/list), [videos.list](https://developers.google.com/youtube/v3/docs/videos/list). 날짜 필터와 조회수 정렬의 검색 표본이 불완전할 수 있다는 제약도 따른다.

## 방문자 증가를 평가할 기준

9월 30일 생성된 [Keyword Performance Review 36699409862](https://github.com/hhj4861/wp-auto-blog/actions/runs/36699409862)의 아티팩트는 최근 시장 선정 글 19개를 포함했다. 발행 후 첫 7일 집계가 완료된 13개의 합계는 검색 클릭 1회, 노출 19회였다. 나머지 6개의 수집 중 상태를 0회로 합산하지 않았다. 28일 창은 아직 수집 중이다. 이 숫자는 사이트 전체 방문자·전체 검색 유입이 아니다.

9월 8일 기존 사이트 감사는 취업·채용 상위 5개 글이 당시 페이지별 검색 클릭의 61.8%를 차지한다고 기록했다. 새 글의 검색량 점수나 유튜브 조회수만으로 이를 대체할 근거가 없다. 기존 일별 Keyword Performance Review의 URL별 7일·28일 클릭, 노출, 색인 상태를 유지해 새 발견 경로의 결과를 비교한다. 신규 후보의 `youtube_discovery` 출처와 실제 발행 URL을 연결할 수 있도록 선정·큐·발행 이력·일별 성과 보고서에 보존한다. 인기 시드를 추가했다는 사실만으로 유입 증가를 주장하지 않는다.

참고: [Google의 사람에게 유용한 콘텐츠 지침](https://developers.google.com/search/docs/fundamentals/creating-helpful-content). 무관한 유행 주제의 대량 발행보다 실제 독자의 질문에 도움이 되는 원문 근거와 답변을 우선한다.

## 검증 및 반영 절차

- 운영의 실제 독립 심사 실패 자료를 재생해 동일 입력에서 오류 코드·최대 호출·미발행·실패 이력 처리를 확인한다. 과거 실패의 하위 오류를 알아냈다는 뜻은 아니다.
- 시간 초과 후 독립 심사 복구, 부정 판정 유지, 인증 중단, 세 번째 후보 조사, 유튜브 발견→별도 수요 측정→큐 연결을 검증한다.
- 실제 selector/queue/main/pipeline/ledger 코드를 연결하고 외부 모델·HTTP·WordPress만 대체한 통합 회귀에서 최종 심사 복구 시 publish 요청·완료 이력을, 부정/지속 오류 시 draft·발행 이력 미기록을 검증한다. WordPress의 실제 신규 글은 아니다.
- 기존 인증 정책상 작업 브랜치 Actions에서 Codex 구독 인증을 사용할 수 없고 로컬 전용 `.trendpulse-codex/auth.json`도 없다. 개발자 인증 복사, 브랜치 판별 우회, 유료 API 대체를 하지 않았다.
- PR 승인·머지 후 main에서 리뷰 자동포스팅 1회를 실행해야 한다. 새 실행의 선정 시각, 독립 심사, 작성, 최종 심사, WordPress publish 상태와 공개 URL, 큐 완료·발행 이력이 모두 확인돼야 운영 복구라고 판정한다. 발행 전 중단이면 실패 단계와 고정 오류 코드 그대로 보고하고 다른 후보를 무제한 반복하지 않는다.
