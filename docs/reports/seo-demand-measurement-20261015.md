# 검색 노출·수요·수익 병목 측정 방법 — 2026-10-15

결론: 글별로 색인 → 시장 검색 수요 → 노출 순위 → 클릭 → 이용 행동 → 수익을 분리해 측정한다. 노출 0만으로 수요 없음이나 삭제 대상으로 판정하지 않는다. 우선 기존 측정의 누락을 보완하는 것이 필요하다.

이 문서는 조사·측정 설계 결과다. 새 추적 코드, GA4 설정, 제목/본문 변경, 자동 정리 정책은 배포하지 않았다. 기존 도구의 읽기 전용 실행과 기존 보고서 재분석만 수행했다.

## 2. 글마다 다음 질문을 차례로 확인

| 단계 | 측정 데이터 | 구분할 상황 | 다음 행동 |
|---|---|---|---|
| 색인 | URL Inspection의 verdict/coverageState/lastCrawlTime/Google canonical | 검색 대상에 들어갔는가, 중복 주소로 평가되는가 | 수집·noindex·canonical·본문 접근 및 중복/품질 가능성을 원인별 확인 |
| 시장 수요 | 같은 검색엔진·지역·기간의 월 검색량, 계절성/추세, 목표 검색어와 유사 표현 | 검색 자체가 드문가, 다른 표현으로 검색하는가 | 주제/표현/발행 시점 재검토. 정보가 없으면 미확인 유지 |
| 순위/노출 | GSC 페이지×검색어×기기×국가의 노출·순위 | 수요는 있지만 우리 글의 노출 기회가 적은가 | 검색 의도·주제 범위·공식 근거·관련 글 연결·경쟁 결과 점검 |
| 클릭 | 동일 검색어·순위대·기기에서 CTR과 클릭 수 | 표시되지만 선택되지 않는가 | 제목·검색 설명·정보 시점과 검색 결과 형태 검토. 평균 순위 하나로 제목 결함을 확정하지 않음 |
| 이용 행동 | 요약/섹션 실제 노출, 메뉴 선택, 공식/관련/제휴 링크 클릭, 활성 참여 시간 | 필요한 정보를 찾고 다음 행동으로 이어지는가 | 답변 위치·설명·관련 이동 개선. 짧은 방문이 곧 불만족은 아님 |
| 수익 | AdSense PV·총수익·RPM, 제휴 클릭·확정 매출, 실제 운영비 | 유입 문제인가, 수익 모델/단가/전환 문제인가 | 총수익과 순이익 기준 평가. 제휴 클릭을 구매·매출로 취급하지 않음 |

GSC 노출은 우리 사이트가 표시된 횟수이며 시장 전체 검색량이 아니다. 순위가 낮으면 검색 수요가 커도 노출이 적을 수 있다. 노출 없는 글은 순위 값 자체가 없을 수 있으며 이를 100위나 수요 0으로 채우지 않는다. Google Trends의 0~100은 상대 관심도이며 검색량이 적으면 0으로 보일 수도 있다. Keyword Planner의 광고주 경쟁도는 자연 검색의 SEO 경쟁도와 다르다.

## 3. 현재 코드에서 재사용할 것과 부족한 것

- src/gsc_client.py: URL별 필터, 페이지·검색어·날짜 등 차원, data_state=final, URL Inspection을 이미 지원한다. 현재 query는 한 번의 응답만 읽으므로 대량/다차원 수집 시 누락·상위 행 제한·페이지 분할 및 Google의 비공개 검색어 생략을 고려한다.
- scripts/report_keyword_performance.py: 발행 후 7/28일 창과 3일 지연 여유, collecting/unavailable 구분 및 부분 결과 저장이 있다. 전체 공개 글 인벤토리와 연결하고 분할 실행/재개로 시간 예산 누락을 줄일 필요가 있다.
- scripts/gsc_report.py: 오늘까지의 예비 데이터를 포함하고 노출된 URL 수를 색인 수처럼 표현하며, 미노출 글을 정리 후보로 표시한다. 원인 진단에서는 이 표현/판정을 그대로 사용하지 않는다. 기본 결과는 로그 위주라 전체 URL을 결합할 기계 판독용 결과가 필요하다.
- scripts/gsc_index_audit.py: 사이트맵 조회와 Google 색인 조회가 한 실행에 묶여 있어 사이트맵 403만으로 전수가 중단됐다. 현재 공개 URL 목록을 입력받아 색인 조회를 독립 실행하고, 사이트맵 접근 문제는 별도 상태로 남기는 경로가 필요하다. 방화벽 설정을 완화하거나 차단을 우회하는 방법을 기본안으로 삼지 않는다.
- src/keyword_gate.py: Naver SearchAd API 경로가 있다. 월 검색량에는 검색엔진·지역·기간·조회일·추정/미확인 상태를 같이 저장한다. Naver 검색량을 Google 수요로 그대로 해석하지 않는다.
- src/category_reader.js: 메뉴 전환과 자동 스크롤은 있지만 분석 전송은 없다. 기본 GA4 scroll만으로 메뉴형 글을 다 읽었다고 판정할 수 없다.

## 4. 수집할 최소 표와 주기

글 단위 한 행: post_id, canonical URL, 공개 상태, 카테고리, 발행일/변경일, 포맷 버전, 주제/목표 검색 의도, 색인 상태/확인 시각/Google canonical, 검색 수요의 출처/기간, 완결 기간 노출/클릭/CTR/쿼리별 순위, 행동 지표, 수익, 데이터 상태, 검토 사유, 다음 조치.

- 매일: 완결 데이터의 새 구간을 증분 수집. Search Console의 미국 태평양 시간 기준 날짜와 맞춘다. Google·GA4·AdSense의 시간대/집계 정의를 확인해 비교한다.
- 주 1회: 모든 공개 글의 상태와 누락을 확인하고, 색인은 신규·오류·미색인 URL부터 갱신한다. 같은 날짜에 전체 URL을 매번 검사할 필요는 없다.
- 평가: 최근 완결 28일과 직전 완결 28일, 발행 후 동일 연령의 7/28일 표본을 구분한다. 신규 글의 기간 미충족은 대기이지 0점이 아니다.
- 상태: reported / no_reported_rows / collecting / unavailable / insufficient_sample / not_applicable을 구분한다. 데이터가 없어도 노출·순위·수익을 임의 0으로 만들지 않는다.
- 보고서: 단일 종합 점수 대신 색인 점검·순위 개선·클릭 검토·수요 재확인·수익 전환 검토·추가 관찰을 복수 사유로 표시한다. 자동 삭제/초안 전환으로 연결하지 않는다.

## 5. 메뉴형 글의 행동 측정 제안 — 아직 미구현

GA4 관리 설정과 실제 이벤트 수신부터 확인한다. 기존 GA4 외부 링크 click을 재사용할 수 있는지 본 뒤, 필요한 차원만 더한다. 제안 이벤트는 summary_view, reader_section_view, reader_menu_select, official_source_click, related_article_click, affiliate_outbound_click이다. 이 명칭은 제안이며 이미 수집되는 이벤트가 아니다.

섹션 보기의 운영 정의는 해당 섹션의 대표 영역이 화면에 보이고 활성 탭에서 일정 시간 관찰됐는지로 정한다. 긴 섹션은 전체 면적 비율만으로 판단하지 않는다. 메뉴 버튼 클릭만으로 섹션 읽기를 기록하지 않고 숨긴 패널은 제외하며, 같은 페이지 내 중복 노출을 억제한다. 체류는 이해/만족의 증명이 아닌 대리 지표다.

기본 GA4 scroll은 페이지의 90%가 표시될 때 발생한다. 메뉴 전환 시 본문 높이가 바뀌고 코드가 자동 스크롤하므로, 이를 글 완독률로 부르면 오판한다. 전체 보기/개별 보기와 실제 섹션 노출을 나누어 보아야 한다. 건강 글의 개인 체크 결과나 민감 입력값은 수집 대상으로 삼지 않는다.

필수 검증: 대표 글에서 메뉴 전환 전후 중복 없이 이벤트 수신, 숨김 패널 미집계, 공식/관련/제휴 클릭 구분, 광고 코드/요청을 건드리지 않음, GA4에서 실제 수신 확인. 태그 삽입만으로 완료로 보지 않는다. 페이지별 AdSense 수익이 데이터 부족으로 제공되지 않으면 카테고리/사이트 단위로 보고 개별 글의 수익을 추정해 채우지 않는다.

## 6. 좁혀가는 첫 실험

1. 측정 누락 해결: 공개 394편 목록과 검색/색인 결과를 연결하고, 위 8편의 현재 색인을 먼저 재확인한다. 사이트맵 403과 미색인, 원장에만 남은 글, 시간 예산 부족을 분리한다.
2. 클릭 개선 후보 검토: 한국농어촌공사 글은 이전 조회 기간에 140노출·1클릭·평균 6.7위, 엑셀 틀 고정은 85노출·0클릭·9.2위, GSAT 일정은 68노출·0클릭·6.4위였다. 이들은 검색어·기기별 검색 결과와 최신성 검토 후보이며 제목 문제나 수요 부족이 입증된 것은 아니다. 채용 기한/시즌이 지난 글은 상시 글과 같은 기준으로 비교하지 않는다.
3. 표본이 확보되는 후보 5~10편을 선정해 한 가설씩 변경한다. 예: 제목/설명만 변경, 또는 답변 구조만 변경. 비슷한 주제·연령·기기·순위의 미변경 글을 참고 비교군으로 둔다. 지금 트래픽에서는 무리한 A/B 분할보다 가설을 기록한 순차 개선이 현실적이다.
4. 변경 시각과 버전을 기록하고 2주 중간 관찰, 완결 28일 이후 평가한다. 데이터가 적으면 연장한다. CTR은 같은 검색어·순위·기기 구성과 함께 비교하고 노출/클릭/수익을 같이 본다. 동시 포맷 변경·공고 마감·계절성 때문에 단순 전후 차이를 인과효과로 확정하지 않는다.
5. 근거가 쌓인 주제/검색 의도에 작성 자원을 집중한다. 수요와 노출은 충분하지만 수익만 낮은 글을 유입 실패로 분류하지 않는다. 순이익 = 광고 수익 + 확정 제휴 수익 - 실제 작성/이미지/API/호스팅 비용으로 별도 계산한다.

오늘 바꾼 메뉴형 13편은 변경 이력이 있는 관찰군으로 표시한다. 변경 직후의 수익 증감을 효과로 주장하지 않는다. 다음 구현은 기존 수집기의 누락·전체 인벤토리 연결과 행동 계측 보강이며, 이 조사에서는 구현하거나 PR을 만들지 않았다.
