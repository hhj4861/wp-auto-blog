## 원인과 복구

검색어 변환은 엄격히 검증되지만 변환이 잘못되면 적격한 실측 키워드까지 버렸다. 예를 들어 SSD1TB → SSD 1TB는 연속 영문·숫자 토큰 분리 금지에 걸린다. 기존 제안 프롬프트의 띄어쓰기 안내에는 이 제약의 구체적인 설명이 없었다. 운영 로그는 잘못된 제안 문자열을 저장하지 않았으므로 실제 문자열이 이 예시와 같았다고 단정하지 않는다. 운영에서 확인한 사실은 13개 키워드가 변환 오류로 검색 자체를 하지 못했다는 점이다.

- 허용된 실측 후보만 실행 대상으로 바인딩한 다음, 모델 제안이 검증을 통과하지 못하면 제안문을 폐기하고 검증된 원래 검색어로 1회 검색한다.
- 검증 함수 자체는 그대로 유지한다. 숫자·대소문자·단위·검색 연산자를 바꾼 제안은 실행하지 않고 원래 검색어도 유효하지 않으면 복구하지 않는다.
- 보고서에 실제 실행 검색어와 고정 오류 코드, original_keyword_recovery 상태를 남긴다. 잘못된 모델 제안 원문은 기록하지 않는다.
- 검색 결과 심사, 전체 질문의 출처 근거, 독립 심사·최종 편집 검사와 이력 기반 보류는 그대로다. 검색어 복구가 발행 승인을 뜻하지 않는다.
- 기존 failure_code는 변환 오류를 이미 키워드 품질 이력에서 제외하고 있었다. 운영 실패 13개로 이 동작을 회귀 검증하며 데이터나 보류 이력을 지우지 않는다.

## 검증 범위

운영 기록은 키워드·검색량·고정 탈락 사유만 최소 fixture로 보존했다. 모델이 실제로 제안한 검색어는 저장되지 않아 테스트의 띄어쓰기 변환은 합성 재현이다. 외부 검색·본문·모델 응답은 회귀에서 모의하며, 새 복구 경로의 실제 모델·발행 검증은 해당 수정 PR의 승인된 머지 후 main에서 해야 한다.
