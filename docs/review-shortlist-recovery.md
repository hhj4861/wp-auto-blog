# 리뷰 후보가 실제 조사 없이 모두 탈락하는 경로 보완

## 확인한 장애

2026-10-01 [Blog Keyword Select 실행 36801143479](https://github.com/hhj4861/wp-auto-blog/actions/runs/36801143479)은 실측 후보 341개 중 실제 검색·출처 평가를 0건 수행하고 `pool_exhausted`로 종료했다. 조사 대상 18개에 대해 모델이 두 회차 모두 빈 `candidates`를 반환했다. 첫 회차의 `노트북램`, `가벼운무선청소기`는 제외 사유도 없었다. 나머지는 대부분 이름만 보고 구매 목적 불명확·구체성 부족으로 제외했다.

기존 코드는 빈 목록이면 제시한 후보 전부를 해당 실행에서 조사하지 않도록 처리했다. 실제 검색 결과로 판단하기 전의 모델 의견이 조사 자체를 막은 것이 이번 장애의 원인이다. 검색 결과·공식 출처 심사가 실패한 사례와 구분해야 한다.

## 변경

리뷰 카테고리의 정상적인 빈 `candidates: []`에 한해 기존 실측 후보 중 `not_reported`, `purchase_intent_unclear`, `insufficient_specificity` 사유를 제한적으로 조사한다.

- 회차별 최대 2개, 실행 전체 최대 3개. 기존 4회차·25분 시간 제한도 적용한다.
- 제외 의견이 없는 후보를 우선하며 같은 제품군·판단 항목의 반복 조사를 줄인다.
- 기존 검색량 하한, 제품군·구매 판단 항목, 중복, 명시적 제외, 실패 쿨다운, 과거 실패 재시도 한도는 그대로 적용한다.
- 범위 초과·정비 목적·중복·카테고리 불일치의 명시적 제외는 다시 조사하지 않는다.
- 잘못된 응답, 미측정 후보 제안, 검색어 변조를 빈 목록으로 해석하지 않는다. 정상 후보가 일부 있는 응답과 다른 카테고리는 기존대로 처리한다.
- 원래 실측 검색어 그대로 검색한 뒤 기존 검색 품질·공식 본문·기획 범위·발행 자격 검사를 모두 거친다. 모델의 사전 선택 없이 **조사**할 수 있게 하며 발행 자격을 자동 부여하지 않는다.
- 원래 모델 `proposals`와 `skipped`는 보존한다. `research_fallback`은 추가 조사 계획, `research_fallback_attempted`는 실제 평가 시작 후보, `shortlist_research_attempts`는 실행 전체 시도 수다. `measured_fallback`은 추가 조사 계획 유무이며 발행 승인 또는 실제 검색 완료를 의미하지 않는다.

운영 `data/category_market_topics.json`, 발행 이력, 쿨다운을 수동 수정하지 않는다.

## 검증 범위 및 운영 확인

실제 10월 1일 후보명과 제외 의견을 `tests/fixtures/review_empty_shortlist_20261001.json`에 고정했다. 회귀 테스트는 외부 검색량·검색 결과·모델 응답을 모의하고 실제 로컬 검증 및 큐 진입 검사를 실행한다. 현재 검색량이나 실서비스 발행 성공을 입증하는 테스트는 아니다.

머지 후 리뷰 1개 선정 실행에서 실제 평가가 수행되는지, 모든 출처·기획 검사를 통과한 경우에만 발행 큐에 들어가는지 확인해야 한다. 통과 후보가 없는 실행은 계속 발행 보류가 정상이다. 이후 자동포스팅 실행의 실제 발행 결과와 공개 URL을 확인한다.

10월 1일 오전 정시 포스팅 실행이 조회 시점까지 생성되지 않은 별도 현상은 이 변경의 해결 범위가 아니다. 스케줄 지연 원인이 확정되지 않았으므로 cron이나 회차 보호를 변경하지 않았다.

- 운영 워크플로와 같은 Python 3.11.14: 관련 16개 테스트 모듈 **1,187개 통과**. 검증한 5개 핵심 모듈의 합산 커버리지 **95.08%**.
- 실제 빈 후보 이력 재현, 검증 통과 후보만 큐 진입, 검색·출처·기획 심사별 실패 차단, 실행별 최대 3개 제한, 시간 초과, 기존 실패 쿨다운 보존 및 새 실패의 다음 실행 재시도 차단을 확인했다.

- 실제 운영 재선정·포스팅은 아직 실행하지 않았다. 이 문서는 작업 브랜치 검증 기록이며 운영 적용 완료 보고가 아니다.
