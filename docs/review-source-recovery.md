# 리뷰 출처 수집과 검색 심사 복구

## 운영 실패에서 확인한 결함

기준은 PR #69 반영 후 운영 실행 `36823191194`의 보고서다. 노트북SSD의 실제 검색 결과에 `sandisk.com` 제조사 설명이 있었지만 공식 출처 허용 목록에 없었고, 공식 검색 힌트는 삼성 가전 매장과 LG 노트북 페이지로 향했다. 최종 출처는 노트북 본체 사양 세 개였다. 삼성공기청정기필터의 재조사에는 다른 제조사의 공기청정기 본체가 포함됐다.

청소기필터는 검색 결과 10개를 받은 뒤 심사 예외로 탈락했다. `SearchReviewError`가 가진 고정 사유 코드를 상위 처리에서 버렸기 때문에 당시 세부 예외는 복원할 수 없다. 이번 재시도 테스트의 오류 종류는 재현용 주입이며, 당시 운영 오류가 특정 코드였다는 증거가 아니다.

## 변경 동작

- 공식 SSD 제조사 SanDisk·Kingston을 허용하고 SSD 질문의 출처 탐색을 SanDisk·삼성 반도체·Kingston으로 우선 배정한다. 실측 검색어와 검색 결과는 바꾸지 않는다. 도메인 및 HTTPS·리다이렉트 검사는 유지한다.
- 명시된 브랜드와 다른 알려진 제조사의 자료를 제외한다. 중립 기관 비교 자료는 계속 심사할 수 있다. SSD 질문에서는 저장장치 설명을 먼저 보존하고 노트북 본체 사양은 보조 자료로 둔다. 본문·필수 항목 검증은 그대로 적용한다.
- 삼성 반도체 페이지의 실제 `.cm-semi-container` 본문만 추출한다. 쿠키·연락처 오버레이로 빈 본문을 채우거나 발췌의 뒷부분을 차지하지 않게 한다.
- 검색 관련성 심사는 모델 호출·응답 형식·인용 검증 오류에만 후보당 한 번, 전체 선정당 추가 두 번까지 재시도한다. 동일 검색 표본을 사용하며 낮은 관련성 판정은 재시도하지 않는다. 입력 오류·사이트 식별 오류·알 수 없는 예외도 자동 재시도하지 않는다.
- 실패 코드와 시도 이력을 보고서의 `search_review_diagnostics`, 추가 호출 수를 `search_review_recovery_attempts`에 저장한다. 재시도 뒤 정상 반환돼도 관련성·의도·공식 본문·범위·발행 자격 검증을 모두 통과해야 한다. 예외 원문·모델 원문·인증정보는 진단에 넣지 않는다.

## 검증 및 한계

`tests/fixtures/review_sources_20261001.json`은 운영의 실제 검색 표본과 마지막 기획 심사에 들어간 출처를 보존한다. 회귀 검증에서 다른 브랜드 출처 제거, 늦게 수집한 SSD 자료 보존, 실제 인용 검증 실패 후 복구, 정상 부정 판정 유지, 반복 실패·전체 재시도 상한, 실패 시 미선정, 복구 후 기존 선정 검증 통과를 확인한다. 모델 판단 자체는 모의 응답이며 실제 운영 선정 성공을 입증하지 않는다.

2026-10-01 로컬 공개 HTTP 확인:

- [SanDisk 내장 SSD 설명](https://www.sandisk.com/ko-kr/solutions/solid-state-drives/internal-ssds): 6,936자 본문 확보, NVMe·SATA·노트북 호환 안내가 추출됐다.
- [삼성 SSD 설명](https://semiconductor.samsung.com/consumer-storage/ssdupgrade/): 보완된 추출기로 7,912자 발췌 확보, NVMe·SATA 본문 유지 및 쿠키 오버레이 제외를 확인했다.
- [Kingston SSD 설명](https://www.kingston.com/en/ssd/desktop-laptop-workstations): 이 환경에서는 HTTP 상태 오류로 본문을 확보하지 못했다. 읽힌 자료로 취급하지 않는다.

HTTP 확인은 로컬 네트워크의 접근·추출 확인이다. GitHub Actions 네트워크 및 실제 운영 모델의 선정·발행 성공은 별도다. 작업 브랜치에서는 기존 운영 인증 정책 때문에 실제 선정 실행을 할 수 없으므로 PR 머지 승인 후 main에서 검증해야 한다. 운영 데이터, 쿨다운, 인증 정책, 발행 기준은 수동 변경하지 않았다.
