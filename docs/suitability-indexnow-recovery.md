# 주제 심사 형식 오류와 IndexNow 접수 보완 — 2026-10-05

## 확인한 원인과 확인 범위

운영 실행 `37199691708`에서 `엑셀그래프만들기`가 주제 적합성 심사 중
`invalid_schema` 2회로 보류됐다. 실제 후보·출처·진단을
`tests/fixtures/suitability_held_20261004.json`에 보존했다.
실패한 모델 원본 응답은 운영 기록에 없으므로 과거의 정확한 위반 필드는 확정할 수 없다.
현재 코드는 인용·기관명·자료 누락·자료형 등 서로 다른 오류를 하나로 뭉개고,
실패 항목을 알려주지 않은 채 같은 프롬프트를 다시 보내는 문제가 있었다.

IndexNow 전역 엔드포인트는 동일 공개 글에 실제 HTTP 403과
`UserForbiddedToAccessSite`를 반환했다. 공개 인증 파일은 리다이렉트 없이
HTTP 200·내용 일치였고, 검색봇 User-Agent에서도 같았다. robots.txt에는 차단이 없었다.
따라서 로컬에서 확인된 키 파일 누락이나 내용 불일치로 설명되지 않는다.
엔진 내부의 거절 이유 또는 원격 검증봇의 접근 경로는 확인되지 않았다.
동일 요청을 공식 참여 엔드포인트 `https://searchadvisor.naver.com/indexnow`에
제출한 결과 HTTP 200이었다.

## 변경

- 출처 본문 전체를 겹치는 최대 900자 구절로 제공한다. 심사 모델이 출처 인덱스와
  구절 번호를 선택하면 서버가 원문으로 복원한다. 본문을 프롬프트에 이중 복제하지 않는다.
- 기관/대상 명칭은 선택한 원문 안에 있어야 한다. 잘못된 인덱스, 다른 자료의 구절,
  상충하는 직접 인용, 중복·누락 출처, 비정상 자료형은 계속 차단한다.
- 직접 인용 방식의 이전 저장 기록도 동일 원문 검증으로 호환한다. 저장 형식은
  기존 `quote`이며 원본 입력 해시·현재성·질문 범위·부정 판정 검증을 유지한다.
- 오류 항목을 고정 코드와 제한된 행 번호로 기록하고 한 번의 기존 재시도에 전달한다.
  모델 원본 응답·임의 예외·알 수 없는 필드는 로그나 재시도에 복사하지 않는다.
  실행당 추가 호출 4회와 25분 예산 및 중첩 호출의 재시도 제한도 유지한다.
- IndexNow 기본 제출 경로를 검증된 Naver 참여 엔드포인트로 변경한다. 실행당 한 경로에
  한 번 제출하며 403·429 등을 다른 제공자 반복 요청으로 바꾸지 않는다.
- 200 접수, 202 검증 대기, 403 소유권 거절, 429 요청 제한을 구분한다.
  403일 때 공개 파일 점검 결과도 별도로 기록하되 엔진의 거절 판정은 유지한다.
- 정확한 호스트·인증 파일 디렉터리 범위를 검증한다. 기존 단순 문자열 포함 검사는
  다른 도메인의 URL을 잘못 허용할 수 있었다. 10,000건 초과는 조용히 누락하지 않고 거절한다.
- 설정 CLI는 기본적으로 공개 인증 파일만 확인한다. 플러그인 설치·활성화 및 자동 일괄
  제출을 제거했다. `--submit PUBLIC_URL` 또는 `--sitemap URL_SITEMAP`으로 명시적으로 제출한다.
  인증 비밀을 변경하거나 새 서버 권한을 만들지 않는다.

## 검증 및 적용 상태

수정된 CLI로 이미 공개된 https://trendpulse.blog/excel-macro-workflow-2026/ 한 건을
제출해 `key_matches`, `accepted=true`, `http_status=200`을 확인했다.
새 포스트를 발행하거나 기존 글 내용을 수정하지 않았다.
접수 성공은 검색엔진의 실제 색인·검색 순위 보장이 아니다.

관련 통합 회귀 테스트 1,429개를 통과했고, 변경 코드와 설정 CLI의 커버리지는
95.37%다(기준 80%). 치명적 오류 정적 검사와 `git diff --check`도 통과했다.

모델 회귀 검증은 운영 후보·출처에 통제된 응답을 적용한다. 과거 원본 응답을 재생한
검증이나 운영 모델의 재심사 성공이라고 해석하지 않는다.
PR #84는 사용자 승인 후 2026-10-05 01:56:56 KST에 운영 main으로 머지됐다.
머지 커밋은 `67b0dc5c3332f17730be788018b012aff4721606`이며 검증한 코드와 동일하다.
자동포스팅 워크플로의 기준 브랜치와 Hostinger 타이머 요청은 main을 사용하므로
다음 실행부터 변경 코드가 적용된다. 머지된 main 코드의 CLI로 같은 공개 글에 대해
`key_matches`, Naver HTTP 200 접수를 다시 확인했다.
이번 머지 검증에서 새 글을 발행하지 않았으며 운영 모델의 주제 재심사 결과는 아직 확인하지 않았다.
전역 엔드포인트의 403 자체가 해제됐다는 뜻은 아니다.
