# 최신 이슈 발견을 공식 날짜 목록으로 전환 + 검색량 면제

- 목표/담당: Claude. 사용자 결정(2026-10-09): 포스팅 주제는 최신 이슈여야 하며, 공식 발표로 확인된 최신 이슈는 네이버 월간 검색량 기준을 면제한다.
- 기준: main(#96 머지 후). 브랜치 `feat/latest-issue-listings-20261009`.

## 원인 (10/9 09:00 슬롯 실패)

- #96의 최신 이슈 발견은 일반 웹검색에 `after:`/`before:` 날짜 연산자를 붙였지만 `codex_native_search`가 이를 무시했다. 결과는 3월 보도자료 목록·지원금 모음 블로그·당근 업체 페이지 등이라 발견 후보 0건.
- 발견 0건인데도 상시 시드(`신청방법`·`환급금`) 후보를 평가했다. 이 후보는 최신 이슈 검사를 통과할 수 없어 조사 예산만 썼다.
- 버전 변경(v7)으로 기존 재고가 모두 무효여서 대체 발행도 불가.

## 변경

1. `src/latest_listings.py`: 날짜가 붙은 공식 목록에서 전일~오늘 항목만 수집한다.
   - 정책브리핑 보도자료 목록(부처명·날짜): 건강(복지부·질병청·식약처), 취업(고용노동부·인사혁신처), 생활정보(국토부·국세청·행안부·금융위 등), 테크(과기정통부).
   - 공식 피드: 삼성전자 뉴스룸·애플 뉴스룸(리뷰·테크), 구글 코리아 블로그·OpenAI 뉴스(테크·생산성).
   - 한국소비자원 보도자료(리뷰): 「화장지 품질비교」 같은 제품 비교 시험. 인증서 체인이 불완전해 기존 `source_tls`(중간 인증서 고정, 검증 유지)로 받는다.
   - 생산성은 OpenAI 고객 사례 대신 구글 Workspace 신기능 업데이트, 테크에 SK하이닉스 뉴스룸 추가. 두 호스트는 정확한 호스트만 공식 뉴스 호스트로 등록했다(같은 플랫폼의 임의 블로그는 불인정).
   - 피드의 `http://` 링크는 `https://`로 올려 검증된 HTTPS로만 읽는다. Atom은 작은따옴표·`rel='alternate'` 링크를 쓴다.
   - 정책브리핑 RSS는 서비스 중단이라 목록 HTML을 읽는다. 목록이 창보다 오래되면 페이지 넘김을 멈추고, 실패한 출처는 건너뛴다.
2. `select_latest_issues`(market_topics): 목록 → 본문 재조회(`fetch_source`) → 원문에 실제 있는 키워드 추출(`latest_issues.extract_keywords`) → 공식 원문 전용 기획(`evidence_mode='latest_issue'`) → 적합성 심사 → 최신 이슈 심사. 네이버 수요·SERP·추세 조회는 하지 않는다. 목록에 항목이 없으면 상시 후보로 넘어가지 않고 `no_latest_listing_items`로 보류한다.
3. 검색량 면제는 `evidence_mode='latest_issue'` + `demand_scope='latest_issue_exempt'` + `monthly_search is None` 세 조건이 모두 맞을 때만 허용한다. 출처 정보(목록 URL = 대표 출처, 목록 날짜가 창 안, 검증 본문 해시)를 새로 검사하고, 검색결과·CAK 필드가 있으면 거부한다. 상시 항목은 라벨을 바꿔도 면제받지 못한다.
4. 점수는 트래픽 추정이 아니라 같은 날 발표 우선(당일 10 / 전일 5 + 15). 재고 판정 때 다시 계산해 변조를 막는다.
5. 하류: 작성 단계 검색 수요 게이트(`evaluate_keyword`)와 최종 의도 검수의 검색 근거 요구를 최신 이슈 브리프에서만 면제한다. 최신 이슈 검사·적합성·중복·출처 재조회는 그대로다.
6. `selection_version` 8. 기존 v7 재고는 무효(어차피 최신 이슈 근거가 없음).

- 생산성은 Workspace 영문 업데이트 위주라 하루 0~2건 수준이다. 리뷰는 소비자원 비교 시험이 없는 날 보류될 수 있다.
