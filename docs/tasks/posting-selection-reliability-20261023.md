## 구현 결과

1. 선정·재고 선택·작성기가 같은 의미 중복 정책을 사용한다. 선정 중 거절한 후보는 버리고 다음 검증 후보로 진행하며, 작성 직전 검사는 안전장치로 유지한다.
2. 작성기가 거절/사용/보관한 키워드는 새 조사와 보고서 재사용 및 큐 적재에서도 되살리지 않는다. 완료·held_draft·skipped_duplicate 이력 보존.
3. 새 적재가 기존 유효한 예비 주제를 보존한다. 동일 키워드 교체와 만료 근거만 superseded 처리. 카테고리별 2개 미만이면 사전 보충 대상.
4. 예약의 선호 카테고리가 실패하면 기존 타 카테고리 재고를 우선 사용한다. 그것도 없으면 다른 카테고리 새 조사를 시도하고 첫 검증 성공에서 중단한다. 복구 조사는 카테고리별 약 3분·총 약 12분 예산이며 진행 중 I/O는 즉시 취소되지 않는다. 인증/사용량 등 치명적 제공자 실패는 카테고리를 바꿔 반복하지 않는다.
5. 완전한 WordPress 목록을 현재 Actions 실행·인증 설정에만 묶어 180초 재사용한다. 일부 페이지·만료·다른 실행의 자료는 재사용하지 않는다. 발행 직전에는 캐시를 무시한 실시간 조회를 강제한다.
6. 작성/조사 전에 연결을 확인하고 일시 연결/타임아웃/502~504만 제한 재시도한다. 인증·TLS·형식 오류는 즉시 중단한다. DNS/연결거부 등 안전한 코드와 별도 ‘기존 글 목록 조회’ 알림 단계를 기록한다.
7. 시장 큐의 고정 5개 스킵 제한 때문에 다음 후보를 못 쓰는 경로를 없앴다. 후보가 모두 소진되면 빈 성공 대신 기존 안전 종료 코드 3을 유지한다.
