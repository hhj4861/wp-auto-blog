# 먼저 발행하고 텔레그램 답장으로 쿠팡 상품 추가하기

새 상품 홍보글은 본문·출처·중복·품질 검수를 통과하면 **상품 링크 없이 먼저 공개**합니다. 발행 확인 후 텔레그램으로 글 주소와 상품 검색어를 안내하고, 사용자가 상품명·단축링크를 답장하면 검수 후 **같은 공개 글에 상품 영역과 광고 고지만 추가**합니다. 30분 대기나 답장 기한은 없습니다. 답장이 없으면 현재 글을 유지합니다.

## 적용 대상

- 검증된 시장 키워드 큐에서 편집자가 `article_type: product_promotion`으로 지정한 상품 홍보·추천·비교 글에만 적용합니다.
- 일반 정보글은 기존처럼 검수 후 발행하며 상품 요청을 보내지 않습니다. 자동 키워드 선정의 기본값은 `information`입니다. 카테고리나 제목의 ‘추천’만으로 상품 홍보글이 되지 않습니다.
- 새 발행이 확인된 큐 항목에 `status: completed`, `post_status: publish`, `affiliate_flow: post_update`, `affiliate_state: waiting`을 기록합니다. 표시가 없는 과거 공개 글에 일괄 요청하거나 링크를 추가하지 않습니다.
- 본문 검수에 실패한 글은 초안으로 남고 상품 요청을 보내지 않습니다. 아직 링크 요청에 연결되지 않은 상품 홍보 초안을 수동 복구하면 검수 후 먼저 발행하고 같은 후속 요청을 등록합니다.

## 사용 방법

1. 자동 포스팅이 글을 먼저 발행합니다. 텔레그램 장애 때문에 최초 발행을 막는 사전 점검은 없습니다.
2. `[포스팅 완료 · 쿠팡 링크 요청]` 메시지에서 **공개 글 주소, 주제, 쿠팡에서 검색할 상품명·용도·선택 기준**을 확인합니다. 맞는 검색어를 정하지 못한 주제는 직접 관련 상품을 확인하도록 안내합니다.
3. 쿠팡 파트너스에서 해당 상품을 확인하고 단축링크를 생성합니다. 시간에 쫓기지 않고 **원래 요청 메시지에 답장**으로 상품마다 한 줄을 보냅니다. 최대 3개입니다.

   ```text
   실제 상품명 | https://link.coupang.com/a/실제발급코드
   ```

   URL은 형식 예시입니다. 실제 상품명과 발급받은 링크를 사용하세요. URL만 보내거나 쿼리 문자열이 붙은 링크를 보내면 수정 안내가 옵니다.
4. `Coupang Telegram Replies`가 답장을 확인합니다. 포스팅 성공 후 후속 실행과 10분 간격 예약 실행을 사용하며 GitHub 실행 지연은 있을 수 있습니다. 30분 대기 단계는 없습니다.
5. 관련성·상품 표현과 새로 읽은 공식 출처를 검수한 뒤 같은 글의 본문에 `관련 상품 살펴보기` 영역과 광고 고지를 추가하고 완료 메시지를 보냅니다. 제목, URL, 원래 발행일, 검색 메타데이터, 카테고리와 대표 이미지를 유지합니다. 본문을 재생성하거나 새 글을 만들지 않습니다.

검색어는 실제 판매 상품을 조회한 결과가 아닙니다. 상품명과 링크가 같은 상품을 가리키는지, 본인 파트너스 계정의 링크인지는 사용자가 확인합니다. 확인되지 않은 가격·최저가·치료 효과·합격 보장을 추가하지 않습니다.

## 검수와 재실행

- 신규 요청에는 키워드 선정 후 36시간이나 요청 후 30분의 발행 대기 조건을 적용하지 않습니다. 이미 발행된 글에 대한 상품 보완이며, 추가 시 상품 관련성과 현재 공식 출처를 다시 검수합니다.
- 안내할 때 저장한 공개 글과 업데이트 직전의 글을 대조합니다. 중간에 본문·제목·메타데이터·발행일 등이 바뀌었거나 비공개로 전환된 경우 업데이트를 보류합니다. 변경된 본문을 자동으로 덮어쓰지 않습니다.
- 잘못된 답장은 수정할 수 있습니다. 상품·근거 검수에 실패하면 상품 추가만 보류합니다. 기존 공개 글은 유지됩니다.
- 요청, 답장, 업데이트 의도와 결과는 `data/coupang_requests.json`, 큐는 `data/topic_queue_general.json`에 저장합니다. 업데이트 전 원문은 실행 환경의 `data/editorial-backups/coupang-update-<글ID>-<요청ID>.json`에 보관합니다.
- 요청 발송 의도와 업데이트 의도를 Git에 저장·push한 후 원격 작업을 수행합니다. 중복 답장이나 재실행으로 상품을 두 번 넣지 않습니다.
- `notification_unknown`은 전송 결과 불명입니다. 자동 재전송하지 않으며 실제 메시지와 상태를 대조해야 합니다. 알림 실패 시에도 이미 공개한 글을 초안으로 되돌리지 않습니다.
- 업데이트 응답이 유실되면 한 번 읽어 정확한 결과를 확인합니다. 결과가 불명확하거나 이전 실행이 `publishing`에서 끝났으면 보류하고 자동 재시도하지 않습니다.
- Telegram은 수신하지 않은 업데이트를 최대 24시간 보관합니다. 답장 기한은 없지만 수신기가 장기간 중단되어 답장을 놓쳤다면 원래 요청에 다시 답장해야 할 수 있습니다.

## 기존 초안 요청과 설정

변경 전에 보낸 초안 요청은 공개 글 요청으로 임의 전환하지 않습니다. 기존 요청의 답장·30분 무응답 발행 검증과 36시간 근거 유효기간을 유지하며, 만료·보류 초안을 자동 복구하지 않습니다. 새 요청과 기존 요청은 `affiliate_flow`로 구분합니다.

기존 `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `WP_GENERAL_*`, `CODEX_AUTH_JSON`, `CODEX_SECRET_WRITE_TOKEN` 설정을 그대로 사용합니다. 그룹은 `TELEGRAM_ALLOWED_USER_ID`도 필요합니다. 같은 봇의 `getUpdates`를 다른 수신기가 소비하면 안 됩니다. 웹훅이 있으면 수신을 중단하며 자동 삭제하지 않습니다. 직접 점검하려면 `python scripts/coupang_telegram_worker.py check`를 사용합니다.

모든 관련 Actions는 `trendpulse-general-posting` concurrency와 `queue: max`를 공유합니다. 본문 생성, 알림, 답장 처리가 같은 상태 파일을 동시에 덮어쓰지 않도록 순서대로 실행합니다.
