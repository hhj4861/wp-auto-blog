# WordPress 게시물 목록 접근 진단

2026-09-19 포스팅 실행의 첫 두 시도는 키워드 선정 전 `existing_titles()`에서 `WordPress inventory unavailable`로 중단됐다. 글 생성 및 텔레그램 요청 단계는 실행되지 않았다. 기존 예외 메시지는 HTTP 상태·실패 페이지·응답 형식을 구분하지 않아 인증 오류로 확정할 수 없었다.

## 운영에서 확인한 사실

- 기존 읽기 전용 POC 조회에서 동일 GitHub Secret으로 최신 발행 글을 조회했다.
- 작업 브랜치의 진단에서 실제 목록 조회 조건을 재현했다. 기본 context와 `context=edit` 모두 총 4페이지, 390개 게시물에 HTTP 200을 반환했으며 제목·메타정보 형식도 정상이었다.
- WordPress 연결 정보의 dotenv 변환 전후 값이 일치했고, 셸 heredoc 확장을 일으킬 문자도 없었다. 비밀값 자체는 로그·파일·결과물에 기록하지 않았다.
- 앞선 실패 시점의 구체적인 HTTP 오류는 기존 로그에 남아 있지 않다. 지속적인 인증 장애나 확정된 서버 차단으로 단정하지 않는다. 정상 응답 확인 후 기존 발행 실행을 재개했다.

## 변경

- `POC Inspect Latest Draft`의 `connection_check=true` 옵션은 WordPress 목록만 읽는다. 게시물 덤프·발행·수정은 실행하지 않는다.
- 진단은 허용된 블로그에 기존 운영 인증을 사용하고 리다이렉트는 따르지 않는다. 기본 조회와 편집 context의 페이지별 HTTP 상태·행 수·구조 검증 결과만 출력한다. 각 목록은 최대 20페이지, 요청당 30초로 제한한다.
- 운영 목록 조회 실패 시 안전한 오류 분류와 페이지 번호를 기록한다. 응답 본문·제목·사용자명·비밀번호·원본 예외는 로그에 포함하지 않는다. 중복 확인 실패를 빈 목록이나 발행 허용으로 처리하지 않으며, 인증 실패의 무조건 재시도도 추가하지 않는다.

검증은 목록 조회·키워드 선택 회귀와 진단의 비밀정보 비노출·전체 페이지 순회·잘못된 대상 차단을 포함한다. 이 변경은 장애 진단을 보강하며, 기존의 일시적인 접근 오류를 코드로 해결했다고 주장하지 않는다. 운영 main 반영은 PR 머지 승인 이후다.

## 복구 확인

관련 테스트 408개가 통과했다. 운영 발행 실행의 세 번째 시도는 기존 main 코드로 정상 완료됐고, 게시물 1760의 발행 상태를 WordPress API로 확인했다. 공개 URL은 https://trendpulse.blog/cholesterol-lowering-habits/ 이며, 별도 비로그인 조회에서도 HTTP 200·일치하는 canonical·본문 존재를 확인했다. 글은 정보형으로 발행됐으며 제휴 링크 요청 대상은 없었다.

조회 장애는 재현되지 않는 상태로 복구됐지만 최초 실패의 정확한 HTTP 원인은 확정할 수 없다. 이 PR의 진단 보강이 이미 운영에 적용돼 장애를 해결한 것으로 보고하지 않는다.
